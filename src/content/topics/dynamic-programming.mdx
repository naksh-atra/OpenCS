## Intuition

Dynamic Programming (DP) is just **recursion + memorization**. When a recursive solution solves the same subproblems repeatedly, we store the results in a table and look them up instead.

Think of it like this: if computing Fibonacci(5) requires Fibonacci(4) AND Fibonacci(3), and Fibonacci(4) ALSO requires Fibonacci(3) — we're computing Fibonacci(3) twice! DP computes it once and reuses.

## Formal Concept

### Two Approaches

**1. Memoization (Top-Down)**
- Start with the original problem
- Recurse but cache results
- Only compute each subproblem once

**2. Tabulation (Bottom-Up)**
- Start with base cases
- Fill the table iteratively
- Usually faster (no recursion overhead)

### When to Use DP

Two properties must hold:
1. **Optimal substructure**: Optimal solution contains optimal solutions to subproblems
2. **Overlapping subproblems**: Same subproblems are solved multiple times

### Classic Problems

**Fibonacci**: `F(n) = F(n-1) + F(n-2)`, base: F(0)=0, F(1)=1

**LCS (Longest Common Subsequence)**:
```
if s1[i] == s2[j]: dp[i][j] = dp[i-1][j-1] + 1
else:              dp[i][j] = max(dp[i-1][j], dp[i][j-1])
```

**0/1 Knapsack**:
```
if weight[i] > w:  dp[i][w] = dp[i-1][w]
else:              dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i])
```

## Step-by-Step Example

### Fibonacci(6):

| n | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| F(n) | 0 | 1 | 1 | 2 | 3 | 5 | 8 |

- F(0) = 0 (base)
- F(1) = 1 (base)
- F(2) = F(1) + F(0) = 1 + 0 = 1
- F(3) = F(2) + F(1) = 1 + 1 = 2
- F(4) = F(3) + F(2) = 2 + 1 = 3
- F(5) = F(4) + F(3) = 3 + 2 = 5
- F(6) = F(5) + F(4) = 5 + 3 = 8

## Common Mistakes

1. **Not identifying the recurrence** — The hard part is figuring out `dp[i] = some function of dp[j] where j < i`. Practice pattern recognition.

2. **Wrong base cases** — Off-by-one errors in base cases cascade through the entire table. Always verify dp[0] and dp[1].

3. **Confusing subproblem definition** — "dp[i] = LCS of first i chars" is different from "dp[i] = LCS ending at char i".

4. **Forgetting the backtrack** — Computing the value is often easier than reconstructing the solution. Store choices made.

5. **Using O(n) space when O(n²) is needed** — Sometimes you need the full table for backtracking, not just the last row.
