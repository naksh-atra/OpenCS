## Intuition

A heap is a complete binary tree where every parent is smaller (min-heap) or larger (max-heap) than its children. It's the perfect data structure when you always need the minimum or maximum element — like a priority queue in a hospital ER, where the sickest patient is treated first.

The root is always the extreme (min or max). After extracting it, the heap reorganizes itself in O(log n) time.

## Formal Concept

### Heap Property

**Min-Heap:** Every parent ≤ its children. Root = minimum.
**Max-Heap:** Every parent ≥ its children. Root = maximum.

### Array Representation

A heap is stored as a flat array — no pointers needed!

For element at index `i`:
- Parent: `⌊(i-1)/2⌋`
- Left child: `2i + 1`
- Right child: `2i + 2`

| Index | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|-------|---|---|---|---|---|---|---|
| Value | 1 | 3 | 2 | 5 | 4 | 7 | 6 |

```
        1          ← Root (minimum)
       / \
      3   2
     / \ / \
    5  4 7  6
```

### Operations

**Insert — O(log n)**
1. Add element at the end of the array
2. "Bubble up": swap with parent while heap property is violated

**Extract Root — O(log n)**
1. Save root value
2. Move last element to root
3. "Bubble down": swap with smaller child (min-heap) while heap property is violated

**Build Heap — O(n)**
1. Start from last non-leaf node
2. Bubble down each node
3. Result: valid heap from unsorted array

### Heap Sort — O(n log n)

1. Build a max-heap from the array
2. Repeatedly extract the root (maximum)
3. Place extracted elements at the end
4. Result: sorted array

## Step-by-Step Example

### Build Max-Heap from [4, 2, 7, 1, 5, 3]

Start from last non-leaf (index 2, value 7):

**i=2 (value 7):** Children are 3 and 6. 7 > 3, no swap needed.

**i=1 (value 2):** Children are 1 and 5. 5 > 2, swap 2 and 5.
Array: [4, 5, 7, 1, 2, 3]

**i=0 (value 4):** Children are 5 and 7. 7 > 4, swap 4 and 7.
Array: [7, 5, 4, 1, 2, 3]
Now check position 2 (value 4): children are 3 and 6. 4 > 3, done.

Result: [7, 5, 4, 1, 2, 3] — Valid max-heap!

### Insert 6 into Min-Heap [1, 3, 2, 5, 4, 7]:

1. Add 6 at end: [1, 3, 2, 5, 4, 7, 6]
2. Index 6, parent index 2. Compare 6 with 2. 6 > 2, stop.

Result: [1, 3, 2, 5, 4, 7, 6]

### Insert 0 into same heap:

1. Add 0 at end: [1, 3, 2, 5, 4, 7, 6, 0]
2. Index 7, parent index 3. Compare 0 with 5. 0 < 5, swap → [1, 3, 2, 0, 4, 7, 6, 5]
3. Index 3, parent index 1. Compare 0 with 3. 0 < 3, swap → [1, 0, 2, 3, 4, 7, 6, 5]
4. Index 1, parent index 0. Compare 0 with 1. 0 < 1, swap → [0, 1, 2, 3, 4, 7, 6, 5]

Result: [0, 1, 2, 3, 4, 7, 6, 5] — 0 bubbled all the way to root!

## Common Mistakes

1. **Confusing heap with BST** — In a BST, left < parent < right. In a heap, parent < both children (min-heap) — there's no ordering between left and right children.

2. **Thinking build heap is O(n log n)** — Most nodes are near the bottom and bubble down very little. The math works out to O(n).

3. **Forgetting it's a complete binary tree** — Heaps are always complete (filled left to right). This guarantees O(log n) height and efficient array storage.

4. **Using index 1 as root** — Some textbooks use 1-based indexing. This codebase uses 0-based, so parent = `(i-1)/2`, children = `2i+1` and `2i+2`.

5. **Not handling equal values** — Heap property allows equal values between parent and child. Don't swap equal values unnecessarily.
